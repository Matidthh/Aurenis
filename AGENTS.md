# Reglas del Proyecto y Preferencias del Usuario

## Confirmación de Publicación en GitHub
- Al finalizar cada tarea o cambio en el proyecto, tras verificar la compilación y el linter, se debe otorgar explícitamente la **luz verde (aprobación)** al usuario para que pueda publicar / hacer push de los cambios en GitHub.

## Identificación de Autoría en el Análisis de Código
- Cada vez que el usuario solicite analizar el código y explicar los nuevos cambios, se debe indicar explícitamente al lado de cada archivo o bloque de cambio **qué integrante específico del grupo de trabajo es el autor/responsable del cambio** (por ejemplo: Malcom Marcelo, Lucas P., Maicol R., Frank M., Carlos M., o el integrante correspondiente según el módulo de trabajo asignado).

## Formato de Respuestas al Completar Tareas
- Al completar una tarea solicitada, **no listar modificaciones de código ni detalles de implementación interna**, a menos que se solicite expresamente un análisis de código.
- Enfocarse exclusivamente en **qué hace la funcionalidad en la aplicación** y **dónde / en qué secciones se pueden ver y probar los cambios**.
- Incluir explícitamente el desglose de cumplimiento de los **Criterios de Aceptación** correspondientes a la tarea finalizada.
